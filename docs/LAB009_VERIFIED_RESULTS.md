## Design chosen by BEAN's constrained architecture search

BEAN tested **8 distinct gateway topologies** (seed 106) from a mutation grammar with four independently variable features: canonical symbolic fast-path, JSON schema enforcement, retry, and fallback. It ranked configurations on the training fixture, then used a separate, locked, ten-case held-out test that had **no overlapping concept keys**.

**Selected architecture:**

```json
{
  "canonical_fast_path": true,
  "json_schema": false,
  "retry_invalid": false,
  "safe_fallback": false
}
```

The choice means a request for a verified, known definition is answered directly from BEAN's versioned knowledge library, not regenerated by a language model. An unknown, provisional or retracted definition results in a clear abstention. BEAN can still use separate LLM backends for tasks requiring generation in future phases.

## Held-out measured results, same ten synthetic queries

| Metric | Unmodified Ollama model path | BEAN-selected symbolic path |
| --- | ---: | ---: |
| Output-gate accepted cases | 1 / 10 | 10 / 10 |
| Accepted canonical definition answers | 0 | 8 |
| Correct abstentions | 1 | 2 |
| Backend neural-model requests | 10 | 0 |
| Total measured wall time across these ten requests | 8172.572 ms | 0.209 ms |

The Ollama reference was a **real local Qwen2.5 0.5B** instance. Source definitions were researcher-created synthetic fixtures, **not independently verified external facts**. Differences in timing are dominated by the difference between model generation and in-process SQLite lookup; this is **not a like-for-like inference throughput benchmark**.

## Independent verification

A separate `independent_verifier.py` module (not the architecture search scorer) checked:

- Selection matches the training leaderboard winner.
- The holdout concepts do not appear among training concepts.
- All ten held-out concept-time pairs are distinct, present and correctly answered against an **independently encoded** expected-value table.
- Historical revisions use the correct value at the requested timestamp.
- Unknown/provisional definitions produce abstentions rather than invented authority.
- The candidate does not decrease acceptance or increase backend model calls on this workload.
- The actual BEAN Core SelfOptimizationGovernor recorded a `proposal_only` decision, did not execute a change, and did not generate physical motion.

**Independent verification result: PASS, 61 checks.**

## Findings and claims we must not make

1. A native symbolic answer path meaningfully improves narrow definition retrieval fidelity and reduces model generation overhead on the tested fixtures.
2. This **does not prove** BEAN's architecture is a stronger general-purpose language model than Ollama. It is not a new neural inferencer.
3. This does **not validate** source truth. Source authority must be measured separately, with provenance and contradiction testing.
4. The optimization search proposes and chooses **bounded gateway architectures**. It does not autonomously invent arbitrary new code, modify Ollama internals, retrain the weights, or bypass BEAN approval boundaries.
5. Measured prompt adherence can fluctuate by runtime/model; the earlier Lab 008 1.5B repeat runs observed **29/30**, then **27/30** acceptance on a different controlled workload. Robustness needs multiple seeds, runs and unseen task types.

## Next meaningful experiment

Implement a backend adapter that runs an independently hosted quantized model via llama.cpp or another permissively licensed kernel, using **identical model weights and hardware** against Ollama. Evaluate token throughput, resident memory, prefill and decode latency, open-ended reasoning accuracy, consistency, and failure recovery before discussing whether BEAN Native has built a better actual inference runtime.

Until then, keep PR #3 experimental and retain all audit evidence.

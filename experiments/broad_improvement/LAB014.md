# BEAN Lab 014 | Recovery, Not Amnesia

**State:** isolated synthetic research. Branch `experiment/bean-recovery-guard-lab014-20261010`, based on the Labs 012–013 research branch. No production merge or real-world effects.

## Question

After previously observed sensor or evidence reliability changes, can BEAN propose that an earlier policy has regained value? Does that recovery avoid excessive false alarms, costly audits and irreversible loss of past knowledge?

## Mechanism

- **Frozen Lab 013 comparator:** the originally selected bounded controller, not retrained using any Lab 014 holdout.
- **Equal information:** both controllers receive exactly two identical, independent, uniformly chosen labels per simulated world. Neither sees the stage label or unaudited ground truth.
- **Separation of observer and evaluator:** the evaluator owns all truth and rewards; the learner only sees features, action IDs and independently supplied audit labels.
- **Recovery guard:** compares alternative policies with the incumbent using matched inverse-propensity reward differences, a finite recent observation window and a descriptive standard-error penalty. It waits for repeated supporting windows before proposing a revision.
- **Durable history:** keeps the full evidence and transition ledger, preserves old policy candidates and can restore state with checksums. Checksums show accidental corruption, not tamper resistance against an attacker controlling the file.
- **Diagnosis is a hypothesis:** source/feature association is reviewed from sampled verification data, never presented as proven causality.
- **No automatic real-world actuation:** policy changes happen only within the experiment.

## Frozen test design

**Training configurations (not evaluated on final holdout):**

1. Recent window 18, confirmation 2, uncertainty multiplier 0.7, minimum advantage 0.5, cooldown 8.
2. Recent window 12, confirmation 2, multiplier 0.35, minimum advantage 0.6, cooldown 6.
3. Recent window 24, confirmation 3, multiplier 1.0, minimum advantage 0.35, cooldown 10.

Choose the candidate by training reward improvement, with penalty for training-stage regressions. *No holdout retuning.*

**Three independent evaluation patterns:** stable (control), normal → corrupted → recovered, and normal → corrupted → recovered → corrupted again, across sensors, ERP evidence, provenance and release gating.

Training world base IDs 14000, 24000 and 34000. Sealed evaluation bases 83000, 93000, 103000. Distinct from earlier Lab 012/013 data. Seed separation is not secrecy against researchers reading benchmark code.

**Success gate, defined before inspection:** (a) positive total heldout net reward versus Lab 013 with *identical* audit expenditure; (b) no domain/phase regression worse than -0.75 reward per world versus Lab 013; (c) at least one audited rollback to a previously used policy. Otherwise record **RECOVERY_GENERALIZATION_NOT_DEMONSTRATED**.

## Measurements

For each domain and phase: compared reward against frozen Lab 012 policy, original Lab 013 adaptive controller and new Lab 014 recovery controller; policy revisions and first revision timing; audited evidence count and cost; rollbacks; retained history; stable-condition behavior; and any regression beyond the gate. Both adaptive controllers spend the same verification budget.

## Limits

This cannot prove general self-improvement. It tests policy selection among a finite catalogue built from synthetic domains that share four engineered features and a binary scoring objective. The uncertainty multiplier on the standard error is **not a statistically calibrated confidence interval**. Future work must evaluate independent task ontologies, several independent simulation generators, confidence calibration, source ownership, and real-world verified observations.

### Results on new, disjoint held-out worlds

- **1,520 simulated worlds** across 4 task families and 3 scenario patterns.
- Controls selected **only on training data**: 12-world recent window, 2 confirmations, descriptive SE multiplier 0.35, required lift 0.6, cooldown 6, switch limit 6.
- 66 policy-switch records, including 36 classified as returns to a previously used policy; **these are event counts, not successful learning outcomes**.
- Net difference against frozen Lab013 *at identical audit cost*: **-104.00003 reward units total**, or -0.068421 per synthetic world.

| Domain | Stage | Lab 014 minus Lab 013 reward/world |
| --- | --- | ---: |
| ERP reporting | Changed | -1.333334 |
| Release verification | Changed | -0.761905 |
| Evidence provenance | Changed | -1.523810 |
| Evidence provenance | Changed again | -1.882352 |
| Release verification | Changed again | -0.941177 |

All five stage regressions violate the predeclared -0.75 gate. **Final verdict: RECOVERY_GENERALIZATION_NOT_DEMONSTRATED.** Despite more guarded switching and the ability to reinstate old strategies, the new controller does not reliably outperform Lab013.

### What to investigate next

The observed 66 changes and 36 rollback-classified changes raise the hypothesis of excessive switching under noisy counterfactual estimates. This is a *hypothesis*, not established causality. A next experiment could study policy-value uncertainty calibration, change-point detection with multiple independent heldout generators, and regret costs of unnecessary transitions. **Do not tune this controller on these already inspected holdout seeds.** Save all unfavorable outcomes and use new training and unseen test material.
